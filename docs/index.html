Abstract

The lexicon is a notation for drawing activity maps of human–AI work from ethnographic fieldnotes: who or what did each step, on which screen, and how each claim was checked. The tool drafts these maps with an open AI model that runs on the researcher's own computer, so notes from hospitals and firms never leave it. With many maps side by side, researchers can build their own explanations of why one person checked the AI and another did not. Radiology is the base case, from 25 months of fieldwork; software development and legal work are synthetic extension cases.

Note

No AI model runs on this page. Every map shown here was coded by hand. Checking and scoring run in your browser with the same rules as the tools in the repository.

Overview

Each map describes one episode, from the moment an item of work arrives to the moment its result is recorded. It has three layers: the workflow (steps, software, screens and how one step led to the next), the claims (each finding and whether it was accepted, checked, referred or set aside) and, optionally, the argument (where the reasoning broke down and how it was repaired).

Status
  • Built and checked: the lexicon, three radiology vignettes, the checker, drawing, scoring, event-log export and the local extraction pipeline.
  • Built, synthetic: software development and legal work, one map each. They show the lexicon carries over; they are not fieldwork.
  • Not yet tested: drafts from a real model on real fieldnotes (Stage 2). No accuracy claim is made here.

Lexicon

Coding rules

  1. Only acceptance closes a claim.
  2. Validation means checking against something independent.
  3. Unexamined agreement: flag a claim that closed only because person and AI agreed.
  4. AI claims point to an AI step.
  5. AI role follows the screen: queue is triage, work is support, record is second opinion.
  6. One meaning per term. Shorthand is accepted only as a hint.

Adding your own setting

Answer six questions from your fieldnotes: the screens and their roles, the software and which of it is AI, the activities, the AI tools and what they show, what counts as an independent check, and one worked example. Save it as domains/<name>.json and run the tools with --domain <name>.

This is how drafts are checked during testing. Each layer gets a score from 0 to 1, with what is missing or extra. The example draft is hand-made with typical errors. You can also paste any map written in the schema.

Use it

Requires Python 3, jsonschema and Graphviz. Extraction also needs Ollama and one open model. Download the repository, unzip it, then:

sudo apt install python3-jsonschema graphviz
cd dcog-lexicon/tools
python3 validate.py ../gold/*.json
python3 render.py ../gold/*.json --layout levels
python3 extract.py note.txt --domain legal

The repository includes the codebook (LEXICON.md) and a step-by-step guide for researchers who do not program (GUIDE.md).

Data and ethics
  • Real fieldnotes stay on the researcher's machine, and the model runs there too.
  • Public files use roles, never names, and quote only published text. The field site and its products are not named.
  • Synthetic and illustrative notes are labelled as such.
